# download-speed-test

Консольный скрипт на JavaScript для Node.js: выполняет **10 последовательных
скачиваний** по HTTP/HTTPS, измеряет каждое до полного получения тела ответа
и показывает общую скорость в **Mbps**. Файл не сохраняется на диск и не
накапливается целиком в памяти. Сторонних зависимостей нет.

## Требования и запуск

Нужен **Node.js 20 или новее**. npm поставляется вместе с Node.js и используется
только для удобных команд запуска. Установка пакетов (`npm install`) не требуется.

Скачайте или клонируйте этот репозиторий, откройте терминал в его папке:

```sh
cd download-speed-test
node --version
node download-speed-test.js "https://example.com/image.jpg"
```

Замените адрес на прямой URL доступного файла. `example.com/image.jpg` — пример
синтаксиса, доступность файла по этому адресу не предполагается. URL с `&` и другими
специальными символами передавайте в кавычках.

Эквивалентный запуск через npm:

```sh
npm start -- "https://example.com/image.jpg"
```

По умолчанию одно скачивание ограничено **30 000 мс**, включая всю цепочку
редиректов. Для большого или медленного файла можно увеличить этот предел:

```sh
node download-speed-test.js "https://example.com/image.jpg" --timeout-ms 120000
node download-speed-test.js --help
```

`--timeout-ms` указывается после URL; значение — целое число от 1 до 2147483647 мс.
Число скачиваний всегда равно 10 и не настраивается.

## Алгоритм и границы измерения

1. Проверить URL через `URL`: разрешены только `http:` и `https:`.
2. В цикле из 10 итераций запустить GET и дождаться всего тела ответа с помощью
   `for await...of`. Только после этого переходить к следующей итерации.
3. Подсчитать `chunk.byteLength` каждого полученного буфера. `Content-Length`
   не используется для расчёта объёма.
4. Измерить длительность через `performance.now()` непосредственно перед
   началом GET и после чтения последнего буфера конечного ответа.
5. Напечатать результат итерации. После 10 успешных итераций рассчитать итоги
   по точным значениям; округлять только при выводе.

В длительность входят создание запроса, DNS (если требуется), установка TCP/TLS,
ожидание сервера, заголовки, все тела ответов и обработка потока в Node.js.
Для каждого GET создаётся новое соединение (`agent: false`). Время запуска процесса,
проверки аргументов, печати результатов и промежутки между итерациями не входят
в сумму длительностей. Поэтому это не полное время работы программы.

### Редиректы

Поддерживаются 301, 302, 303, 307 и 308, относительные и абсолютные `Location`,
переходы между HTTP/HTTPS-адресами. Допускается максимум 5 переходов в одной
итерации. Перед переходом тело промежуточного ответа читается полностью.
Протокол назначения проверяется заново. Отсутствующий или некорректный `Location`
и превышение лимита считаются ошибками.

**Без редиректов выполняется ровно 10 HTTP GET. При редиректах выполняется
ровно 10 последовательных замеров, но фактических GET будет больше**, поскольку
каждый переход требует отдельного запроса. Например, один редирект на итерацию
даёт 20 GET. Следующая итерация снова начинается с исходного URL.

Байты тел промежуточных ответов включены в объём соответствующей итерации;
их время также включено в её длительность. Таким образом, учитываются все
фактически прочитанные тела, а не только конечный файл. Повторных попыток нет.

### Формулы и единицы

Для каждой итерации `i`:

```text
durationSeconds_i = durationMs_i / 1000
speedMbps_i = bytes_i * 8 / (durationSeconds_i * 1000000)
```

Для всех 10 итераций:

```text
totalBytes = sum(bytes_i)
totalDurationSeconds = sum(durationMs_i) / 1000
averageDurationMs = sum(durationMs_i) / 10
overallSpeedMbps = totalBytes * 8 / (totalDurationSeconds * 1000000)
```

1 байт = 8 бит; **1 Mbps = 1 000 000 бит/с** (десятичная единица).
Mbps и MB/s различаются в 8 раз. Общая скорость рассчитывается из суммарных
байтов и времени, а не как арифметическое среднее отдельных скоростей.
Пустой успешный ответ даёт 0 байт и 0 Mbps.

## Ошибки

Успешными считаются конечные статусы 2xx. Ошибки HTTP, DNS, соединения, TLS,
обрыв тела, недопустимый URL, редирект или тайм-аут останавливают замер.
Тайм-аут прерывает активный запрос через `AbortController`; он действует на всю
итерацию и не сбрасывается после получения очередного блока или редиректа.

При ошибке сообщение выводится в stderr, код завершения — **1**.
Результаты уже завершённых итераций могут оставаться в stdout, но итоговая
сводка не печатается и частичный запуск не выдаётся за успешный.
Код завершения успешного замера и `--help` — **0**.

## Тесты

```sh
npm test
```

Или без npm:

```sh
node --test test/download-speed-test.test.js
```

Путь указан явно: имя основного файла `download-speed-test.js` тоже подходит
под стандартный шаблон поиска тестов Node.js.

Тесты используют `node:test`, `node:assert` и локальные HTTP-серверы на
`127.0.0.1` со свободными портами. Внешние сайты и скорость интернета не нужны.
Проверяются количество и последовательность GET, потоковый подсчёт бинарных
и UTF-8 данных, ожидание последнего блока, формулы, разные размеры и длительности,
пустые и сжатые ответы, редиректы, HTTP-ошибки, недопустимые URL, отказ соединения,
тайм-ауты до заголовков и во время тела, обрыв ответа и поведение CLI.
GitHub Actions запускает тот же набор на Node.js 20/22/24 в Ubuntu и Windows.

## Ограничения точности

- Это прикладная скорость скачивания с выбранного сервера: на неё влияют его
  нагрузка, задержка сети, TLS, CDN, кэши, ОС и загрузка локального процесса.
  Результат не гарантирует максимальную пропускную способность интернет-канала.
- Считаются байты **тел HTTP-ответов**. Заголовки, HTTP chunk framing, накладные
  расходы TCP/TLS и повторные передачи пакетов в объём не входят.
- Отправляется `Accept-Encoding: identity`. Если сервер всё же сжимает тело,
  считается размер полученного сжатого тела: автоматической распаковки нет.
  Это соответствует поведению низкоуровневого [HTTP API Node.js](https://nodejs.org/docs/latest-v20.x/api/http.html).
- Отправляется `Cache-Control: no-cache`, однако поведение сервера/CDN и кэши
  DNS вне контроля скрипта. Содержимое файла между запросами может измениться;
  размер каждого ответа измеряется независимо.
- Небольшие файлы особенно чувствительны к задержкам соединения. Новое соединение
  на каждый GET увеличивает их влияние; на больших файлах оно обычно меньше.
- `performance.now()` измеряет прошедшее время процесса. Таймеры зависят от
  планировщика и event loop; срабатывание тайм-аута может задержаться под нагрузкой.
- Используется HTTP/1.1. Отдельных настроек прокси, cookies, авторизации и HTTP/2 нет.
  Реальный HTTPS/TLS и внешние серверы не входят в локальные автоматические тесты.
